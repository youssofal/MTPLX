# MTPLX 2.13.3

MTPLX 2.13.3 makes high-speed chat streaming smooth at 120 Hz ProMotion when Inkling 2 Mini crosses 200 tok/s, stops copy-lane backoff stalls during `"rewrite it"` code edits, splits long Inkling 2 Mini prefills on M1 and M2 Macs so they stay under the macOS GPU watchdog (#422), speeds up Flash-Next on M5 Ultra (#682), and makes cooling, smaller-Mac memory headroom, settings persistence, and live telemetry tell the truth. Your downloaded packs keep working as they are.

Measured on an M5 Max MacBook Pro (128 GB) comparing the final 2.13.3 build against the pre-polish 2.13.3 base (`24afa03ad`, which already carried the earlier fixes since 2.13.2), with fans pinned at `max` (~7,812–7,838 RPM). In the interleaved `A1 -> B1 -> A2 -> B2` gate, `a1` and `b1` ran under `nominal` thermal pressure, `a2` shifted to `heavy` mid-run, and all of `b2` ran under `heavy` SoC throttling. Separately, the M5 Ultra change (`#682`) was measured against `main` on a 256 GB M5 Ultra before merge.

## 120 Hz ProMotion streaming & Performance mode

- **Chat streaming stays smooth above 200 tok/s.** In 2.13.2, streaming felt smooth around 80 to 90 tok/s, but once copy-lane bursts pushed Inkling 2 Mini past 110 to 200+ tok/s, the chat transcript fell behind the live tok/s counter and stuttered with visible per-line freezes and reflow bursts. 2.13.3 drives reveal pacing at native 120 Hz ProMotion (`60–120 Hz` range on supported panels) with a lag-bounded adaptive pacer (`0.35 s` rate window, `0.15 s` attack, `0.12 s` target buffer lag), doubling copy-lane flush frequency (`51.1 -> 96.2 Hz` HTML, `43.1 -> 81.9 Hz` Markdown), cutting `paint_gap_ms` p95 from `25.0 -> 8.3 ms` (`0` gaps `> 50 ms`), keeping queue lag p95 at `28.1–35.5 ms`, and cutting visual Markdown freezes `> 50 ms` by `78.6%` (`14 -> 3`).

- **Markdown prose and code blocks no longer trigger per-line view-graph churn.** Prose sections now render incrementally through a layer-backed AppKit `NSTextStorage` surface with inline Markdown styling (headings, bold/italic, inline code, links, lists, blockquotes) and height-gated SwiftUI layout updates, while `ChatLiveDecodeObservable` isolates 0.5 s live tok/s chip updates from re-evaluating the conversation view. This reduces SwiftUI item publishes from `684 -> 3` on copy-lane HTML and `156 -> 4` on Markdown while keeping `apply_ms` p95 at `0.32–0.43 ms` and `draw_ms` p95 at `0.30–0.80 ms`.

- **Performance mode uses 30 Hz + lightweight AppKit text rendering.** Turning on Performance mode caps live chat display refreshes at `30 Hz` (`15–30 Hz` range) and routes plain-text streaming through the same zero-churn AppKit surface with Markdown and code-card parsing skipped, reducing WindowServer GPU compositing overhead while MLX decodes.

## Copy-lane speed on edits and rewrites

- **Real `"rewrite it"` edits keep copy velocity instead of locking out.** When a user asked to rewrite an existing file while adding new features (such as neon styling, audio synthesis, and progressive difficulty), edit-boundary rounds that still landed `4–8` tokens on a wide 23-proposal block previously pulled the width-blind acceptance EMA below `0.35`, triggering 64-token lockouts (`140` backoff declines and `7` suspensions in testing) and resetting to 8-row probation. 2.13.3 scores match viability against a probation-sized prefix and steps verify widths smoothly across 8-row tiles while still backing off on genuine zero-match misses, jumping `rewrite_copy_t1` from `87.2 -> 125.5 tok/s` (`+43.9%`, `1,528–1,669` vs `358–843` accepted copy tokens) and eliminating copy suspensions on `coding_repeat_t2` (`118.7 -> 138.7 tok/s`, `+16.8%`).

- **Wide context-copy cliffs fixed.** Fixed wide-panel verify cliffs across BF16 draft-head scoring, Stage C memory spills, GPU verify decisions, 8-row tile alignment, and widest-width runtime warm-up and pool pricing.

- **No regression on cold coding, verbatim repeats, vision, or exactness.** At matched `nominal` thermal state, `coding_cold_t1` ran at `29.87 ms/verify call` vs `30.36 ms/verify call`; under matched `heavy` throttling, `greedy_parity_t1` ran at `78.1 tok/s` (`38.13 ms/call`) vs `78.0 tok/s` (`38.17 ms/call`); peak memory matched to `0.00 GB` (`19.23–23.24 GB`); vision turns preserved full chart recognition (`red`, `green`, `blue`, `120`, `chart`, `mtplx`); and greedy parity hashes matched identically across all 4 ABAB arms.

## M1/M2 long-prompt stability and M5 Ultra speed

- **Inkling 2 Mini stays under the macOS GPU watchdog on long M1/M2 prompts (#422).** On M1 and M2 Macs, long cold full-attention prefills attend over every key read so far and could trip `kIOGPUCommandBufferCallbackErrorImpactingInteractivity`. MTPLX now splits long non-tensor full-attention dispatches along the key axis and flushes Metal command buffers between slices while leaving M5 single-launch untouched.

- **Flash-Next runs faster on M5 Ultra (#682).** Enabled the fused hyper-connection verify read (`hc_verify_read`) on M5 Ultra (`applegpu_g17d`), proven bit-equal at 4 rows against the compiled stock chain. Across 9 requests over 6 alternating boots on a 256 GB M5 Ultra at depth 3, decode sped up `7.5%` to `8.8%` (`21.02 -> 19.54 ms` median verify step) with byte-identical greedy and seeded outputs and unchanged prompt speed. M3 Ultra keeps the stock chain until measured.

## Smarter cooling and smaller-Mac memory headroom

- **Temperature-stepped Smart fan control.** Added a stepped temperature-gated Smart fan curve with separate desktop (Mac Studio, Mac mini, Mac Pro, iMac) and laptop profiles, a short-turn quiet delay (`sensorless_delay_s`), CLI target-RPM verification, and fixes for SmartFanController detach/end-request race conditions so fans restore reliably after requests finish.

- **More headroom on Macs under 48 GB.** Lowered the memory-guard abort floor below 48 GB (`512 MiB` minimum on 8/16 GB Macs and `0.60 GiB` on 24 GB Macs, while keeping every death-signature and compressor guard intact) and stopped double-billing leased Inkling rings in memory accounting.

## Settings, Dashboard, SessionBank, and K3 timing accuracy

- **Settings no longer jump when clicked.** Isolating `SettingsTab` behind a stable projection bridge and moving the dirty Save bar from an animated `.safeAreaInset` to a fixed-clearance bottom overlay eliminates full-tab scroll jumps when toggling options or receiving background 2 s health snapshots.

- **One clear Fan Mode control.** Consolidated the duplicate header and section fan pickers in Cooling into a single immediate-apply segmented Fan Mode control (`Default`, `Smart`, `Max`).

- **Loading a model honors your saved settings.** Added `"inkling2"` to `ModelPickerOverlay` and `MTPLXModelOption` family recognition, stopped passive snapshot/health reads from overwriting `settings.json`, prevented unverified fan-ramp fallbacks from mutating saved `fanMode`, and cleared stale post-stop fan state on restart so saved `fanMode`, `reasoning`, and `reasoningEffort` persist across starts, stops, and model reloads.

- **Speed Truth and Verify Waterfall now split `draft`, `verify`, and `verify_forward` on Inkling 2 Mini.** Calibrated fused stage shares during model warmup (`round_program.py`) split wall time without adding per-round GPU `mx.eval()` barriers. All `7/7` turns in live QA and `14/14` candidate ABAB turns reported non-zero `draft_time_s`, `verify_time_s`, and `verify_forward_time_s` (for example `draft 283.1 ms`, `verify_forward 2,326.1 ms`, `verify_overhead 189.1 ms` with `0` verify/call slowdown).

- **Dashboard, System, Activity, and SessionBank truthfulness:**
  - `System` shows active fan mode (`Max` / `Smart` / `Default`) and dual live RPMs (`7,821 / 7,815 RPM` live in UI) even when background Thermal Polling is off.
  - Tool-call turns track `first_visible_kind` (`"text"` vs `"tool_call"`) and `first_answer_s`, showing `"first tool call at ..."` instead of mislabeling tool-call turns as slow first answers.
  - `/v1/mtplx/snapshot` reports live `model_id`, `model_family` (`inkling2`), live sampler, and `resolved_reasoning_effort` (`xhigh`) in `Activity`.
  - Live-reference KV leases report their real RAM footprint (`6.79 GB` across `7` sessions in live QA; `4.02 GB` across `5` sessions in ABAB) and cumulative RAM/SSD hits (`6` hits in live QA) without `Zero KB` fallbacks or false `superseded_session_lease` eviction noise.
  - `DecodeChart` and `ALL-TIME MAX` share the same ceiling; `CACHED` separates current turn from compact lifetime totals; `AVG PREFILL` shows compact throttled badges; Hero idle shows last turn + 5-min avg; Dashboard tabs add `72–84 pt` bottom clearance above `^ Expand chat`.

## Models, Forge, CLI, and reliability

- **Reuse complete models already on disk.** MTPLX and the app now discover and reuse complete model snapshots stored in `HF_HOME`, `HF_HUB_CACHE`, and Hugging Face–structured folders while enforcing revision, commit-SHA freshness, and completeness checks.
- **Forge Discover catalog improvements.** Raised the Discover limit to `500`, added multi-token separator-insensitive search, and included Inkling 2 Mini in the fallback catalog.
- **Qwen 3.5 embeddings and reranking (#712).** `mtplx/retrieval.py` now resolves nested `language_model.model` backbones when extracting hidden states for `/v1/embeddings` and reranking.
- **Keyed `mtplx stop` support (#422).** `mtplx stop` accepts `--api-key` and `--api-key-file` (and `MTPLX_API_KEY`) and reports `auth_required` clearly on HTTP 401/403 instead of silently exiting.
- **Mid-stream error and disconnect receipts.** Streaming endpoints (`/v1/chat/completions`, `/v1/messages`, `/v1/completions`, `/v1/responses`) log mid-stream errors and emit failure telemetry, and `/v1/completions` client disconnects record cancellation receipts.
- **Prompt cache fidelity and OpenCode 2.3 tracing.** Clone-restored Inkling turns preserve `prompt_boundary_logits` across zero-suffix restores, live recurrent leases validate boundary payloads before shadowing cold SSD near-prefix lookups, and `mtplx trace` supports OpenCode 2.3's `session_v2`, `session_message`, and `session_part` tables alongside legacy schemas.
- **PyPI package metadata (#705).** Updated the PyPI description, keywords, and links for Inkling 2 Mini.

## Experimental, off by default

- **`MTPLX_INKLING_DRAFT_HEAD_BITS` (`4`, `6`, or `8`, unset/off by default).** Builds a compact affine-quantized copy of a dense BF16/FP16 vocabulary head strictly for Inkling draft proposal scoring while leaving target weights untouched. Kept off by default because it allocates an extra quantized copy of the vocabulary head in memory.

## Known in this release

- **Measured primarily on M5 Max (and M5 Ultra for `#682`).** Behavior on M1–M4 Macs and smaller RAM tiers is verified by the M1/M4 Metal fallback rehearsal, `106/106` Inkling launch census across M5/M4/M1 architectures, and automated tests; the `#422` M1/M2 prefill key-split passed Metal parity checks here and awaits on-device confirmation on an M2 Max.
- **macOS thermal throttling behavior is unchanged.** On Apple Silicon, macOS throttles GPU frequency based on SoC temperature (`nominal` -> `heavy` under sustained hot load); use `Smart` or `Max` Fan Mode in Settings during long sessions.

## Upgrading

The app updates itself (MTPLX menu, Check for Updates). With Homebrew: `brew update && brew upgrade mtplx`. With pip: `pip install -U mtplx`. The packs did not change, so nothing needs to be downloaded again. This release is version 2.13.3, build 2013031.
