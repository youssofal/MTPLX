# MTPLX 2.13.3

MTPLX 2.13.3 makes high-speed chat streaming smooth at 120 Hz ProMotion even when Inkling 2 Mini crosses 200 tok/s, keeps copy-lane speed high during real `"rewrite it"` code edits instead of stalling on backoff, and makes the app's settings, speed breakdown, SessionBank, and cooling readouts tell the truth. Your downloaded packs keep working as they are.

Measured on an M5 Max MacBook Pro (128 GB), against 2.13.2 (`24afa03ad`), with fans pinned at `max` (~7,812–7,838 RPM). Note: in the interleaved `A1 -> B1 -> A2 -> B2` gate, `a1` and `b1` ran under `nominal` thermal pressure, `a2` shifted to `heavy` mid-run, and all of `b2` ran under `heavy` SoC throttling.

## 120 Hz ProMotion streaming

- **Chat streaming stays smooth above 200 tok/s.** In 2.13.2, streaming felt smooth around 80 to 90 tok/s, but once copy-lane bursts pushed Inkling 2 Mini past 110 to 200+ tok/s, the chat transcript fell behind the live tok/s counter and stuttered with visible per-line freezes and reflow bursts. 2.13.3 drives reveal pacing at native 120 Hz ProMotion (`60–120 Hz` range on supported panels) with a lag-bounded adaptive pacer (`0.35 s` rate window, `0.15 s` attack, `0.12 s` target buffer lag), doubling copy-lane flush frequency (`51.1 -> 96.2 Hz` HTML, `43.1 -> 81.9 Hz` Markdown), cutting `paint_gap_ms` p95 from `25.0 -> 8.3 ms` (`0` gaps `> 50 ms`), keeping queue lag p95 at `28.1–35.5 ms`, and cutting visual Markdown freezes `> 50 ms` by `78.6%` (`14 -> 3`).

- **Markdown prose and code blocks no longer trigger per-line view-graph churn.** Prose sections now render incrementally through a layer-backed AppKit `NSTextStorage` surface with inline Markdown styling (headings, bold/italic, inline code, links, lists, blockquotes) and height-gated SwiftUI layout updates, while `ChatLiveDecodeObservable` isolates 0.5 s live tok/s chip updates from re-evaluating the conversation view. This reduces SwiftUI item publishes from `684 -> 3` on copy-lane HTML and `156 -> 4` on Markdown while keeping `apply_ms` p95 at `0.32–0.43 ms` and `draw_ms` p95 at `0.30–0.80 ms`.

## Copy-lane edit and rewrite speed

- **Real `"rewrite it"` edits keep copy velocity instead of locking out.** When a user asked to rewrite an existing file while adding new features (such as neon styling, audio synthesis, and progressive difficulty), edit-boundary rounds that still landed `4–8` tokens on a wide 23-proposal block previously pulled the width-blind acceptance EMA below `0.35`, triggering 64-token lockouts (`140` backoff declines and `7` suspensions in testing) and resetting to 8-row probation. 2.13.3 scores match viability against a probation-sized prefix and steps verify widths smoothly across 8-row tiles while still backing off on genuine zero-match misses, jumping `rewrite_copy_t1` from `87.2 -> 125.5 tok/s` (`+43.9%`, `1,528–1,669` vs `358–843` accepted copy tokens) and eliminating copy suspensions on `coding_repeat_t2` (`118.7 -> 138.7 tok/s`, `+16.8%`).

- **No regression on cold coding, verbatim repeats, vision, or exactness.** At matched `nominal` thermal state, `coding_cold_t1` ran at `29.87 ms/verify call` (`b1`) vs `30.36 ms/verify call` (`a1`); under matched `heavy` throttling, `greedy_parity_t1` ran at `78.1 tok/s` (`38.13 ms/call`) vs `78.0 tok/s` (`38.17 ms/call`); peak memory matched to `0.00 GB` (`19.23–23.24 GB`); vision turns preserved full chart recognition (`red`, `green`, `blue`, `120`, `chart`, `mtplx`); and greedy parity hashes matched identically across all 4 ABAB arms.

## Inkling K3 timing breakdown

- **Speed Truth and Verify Waterfall now split `draft`, `verify`, and `verify_forward` on Inkling 2 Mini.** In 2.13.2, Inkling K3 fused rounds left `verify_forward_time_s` at `0.0` and folded fused execution time into `draft_time_s`, leaving the Verify Waterfall incomplete. 2.13.3 calibrates fused stage shares during model warmup (`_calibrate_stage_shares` in `round_program.py`) and splits wall time without adding per-round GPU `mx.eval()` barriers. All `7/7` turns in live QA and `14/14` candidate ABAB turns reported non-zero `draft_time_s`, `verify_time_s`, and `verify_forward_time_s` (for example `draft 283.1 ms`, `verify_forward 2,326.1 ms`, `verify_overhead 189.1 ms` on Verify Waterfall with `0` verify/call slowdown).

## Settings stability and persistence

- **Settings no longer jump when clicked.** Isolating `SettingsTab` behind a stable projection bridge and moving the dirty Save bar from an animated `.safeAreaInset` to a fixed-clearance bottom overlay eliminates full-tab scroll jumps when toggling options or receiving background 2 s health snapshots.

- **One clear Fan Mode control.** Consolidated the duplicate header and section fan pickers in Cooling into a single immediate-apply segmented Fan Mode control (`Default`, `Smart`, `Max`).

- **Loading a model honors your saved settings.** Added `"inkling2"` to `ModelPickerOverlay` and `MTPLXModelOption` family recognition, stopped passive snapshot/health reads from overwriting `settings.json`, prevented unverified fan-ramp fallbacks from mutating saved `fanMode`, and cleared stale post-stop fan state on restart so saved `fanMode`, `reasoning`, and `reasoningEffort` persist across starts, stops, and model reloads.

## Dashboard, SessionBank, and thermal accuracy

- **System tab shows active fan mode and live RPMs.** While `System` is open, a gentle live refresh queries `/v1/mtplx/thermal/status` directly and displays active fan mode (`Max` / `Smart` / `Default`) and dual fan gauges (verified at `7,821 / 7,815 RPM` live in UI, `7,809 / 7,823 RPM` on API) even when background Thermal Polling is off.

- **Tool-call turns are no longer mislabeled as slow first answers.** OpenAI request telemetry and `ActivityTab` now track `first_visible_kind` (`"text"` vs `"tool_call"`) and `first_answer_s`, showing `"first tool call at ..."` on tool-call-only turns.

- **Live `snapshot.profile` matches the loaded model and sampler.** `/v1/mtplx/snapshot` now reports the loaded `model_id` (`mtplx-inkling-2-mini-optimized-quality`), `model_family` (`inkling2`), live sampler (`temperature: 1.0`, `top_p: 1.0`, `top_k: 0`), and `resolved_reasoning_effort` (`xhigh`), displayed directly in `Activity` Agent lane.

- **SessionBank and Engine Sessions report real memory and hits.** Live-reference KV leases now report their actual RAM footprint (`6.79 GB` across `7` sessions in live QA; `4.02 GB` across `5` sessions in ABAB) and cumulative RAM/SSD hits (`6` hits: `4` RAM / `2` SSD in live QA; `4` hits in ABAB) without `Zero KB` fallbacks, and routine `superseded_session_lease` lease handoffs record cleanly outside `eviction_log` (`0` false evictions).

- **Dashboard layout and tile polish:**
  - `DecodeChart` and `ALL-TIME MAX` read from the same consistent series/ceiling so chart peaks never exceed `ALL-TIME MAX`.
  - The `CACHED` tile distinguishes current-turn cache scope from compact lifetime totals (`19K total`) with no awkward truncation.
  - `AVG PREFILL` uses compact throttled badges (`1/4 throttled`) without ellipsis clipping, and Hero gauge idle readouts show both `last turn` and rolling `5-min avg`.
  - Added bottom scroll clearance (`72–84 pt`) on Dashboard tabs so the floating `^ Expand chat` pill never overlaps bottom cards.

## Known in this release

- **Measured on an M5 Max only.** All measurements above ran on an Apple M5 Max MacBook Pro (128 GB); behavior on M1–M4 Macs and smaller RAM tiers rests on shared hardware detection and unit test coverage rather than dedicated 2.13.3 on-device captures.
- **macOS thermal throttling behavior is unchanged.** On Apple Silicon, macOS throttles GPU frequency based on SoC temperature (seen as `nominal` -> `heavy` during sustained uncooled/hot runs); use `Smart` or `Max` Fan Mode in Settings to keep SoC temperatures lower during long coding sessions.

## Upgrading

The app updates itself (MTPLX menu, Check for Updates). With Homebrew: `brew update && brew upgrade mtplx`. With pip: `pip install -U mtplx`. The packs did not change, so nothing needs to be downloaded again. This release is version 2.13.3, build 2013030.
