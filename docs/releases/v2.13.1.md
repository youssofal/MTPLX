# MTPLX 2.13.1

MTPLX 2.13.1 fixes Inkling 2 Mini failing to load on M1 Macs. In 2.13.0 the model stopped while loading on an M1 Max with the error "Thread group size (800) is greater than the maximum allowed threads per threadgroup (704)" (#706). Macs with an M4 or an M5 load it. Whether Macs with an M2 or an M3 were affected is not known: nobody has run 2.13.0 on one yet. ## What changed

- **Inkling 2 Mini now loads on M1 Macs.** While it loads, Inkling 2 Mini prepares the widest panel it uses when the model copies text it has already seen, such as rewriting a file: 25 rows, 24 copied tokens and one more. That panel's attention kernel asks the GPU for a group of 32 threads per row, 800 threads, and an M1 Max allows that kernel only 704. [X1 FIX: what 2.13.1 does instead, in one or two plain sentences, from the pull request.]
- **A source install builds MTPLX's engine with older Xcode tools.** In 2.13.0 a source install (`pip` without a prebuilt wheel, or a development checkout) whose Xcode tools carried an SDK older than macOS 26 could not compile the engine, and MTPLX then ran without it. It now compiles there too. The prebuilt wheels on PyPI for Python 3.11 to 3.14 on Apple silicon carry the engine, and Homebrew installs that wheel.

## If you have an M1 Mac

Update MTPLX, then start Inkling 2 Mini again. The app offers the update itself; with Homebrew run `brew update && brew upgrade mtplx`, and with pip run `pip install -U mtplx`. If you started 2.13.0 with `MTPLX_CONTEXT_COPY_K=7` to get past the error, you can leave that setting out now.
