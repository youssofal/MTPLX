# MTPLX 2.11.2

A recovery update for reliable local coding: safer hardware routing, better
session reuse, consistent CLI setup, and fixes to Hermes and app installation.

## Correct hardware routes

The 27B flash-decoding verify route now requires a supported M5-class GPU and
macOS version. Other configurations use the packed fallback and its startup
self-check. This addresses the unsupported-route failures reported in #459,
#461, #464 and #467. Hardware selection and refusal counters are visible in
`/health`.

This is not a claim of measured speed parity across every Mac. An M5 forced
fallback check exercises routing; actual M1–M4 candidate measurements are
separate evidence. The other short-prompt and idle symptoms in #455 remain
under investigation.

## Preserve work across coding turns

- **Deep sessions (#446):** the resolver recognizes prior turn boundaries so
  an increasing prompt does not lose its session merely because the shared
  prefix falls below the old fraction threshold. Edited histories retain
  their existing matching rules.
- **AR session restores (#465):** stores and lookups use the same history
  policy, fixing `policy_mismatch` when MTP weights are not loaded.
- **Short follow-ups (#454):** a continuing conversation is no longer treated
  as a sessionless background task solely because its requested answer is short.
- **Memory admission (#450/#447):** remeasure after reclamation and return an
  explanatory 507 before prefill if the projection still exceeds the limit.
  Memory limits are unchanged. This does not establish that every deep-memory
  failure or the long-lived growth in #456 is resolved.

## CLI, clients and app

- One-shot and interactive CLI paths apply the same model/runtime contract as
  serving, including Flash-Next's family-specific verifier setup (#463).
- Multi-turn terminal chat keeps reasoning separate from the visible answer
  when rebuilding history, avoiding malformed thinking blocks on follow-ups.
- Hermes inherits root terminal execution settings when its MTPLX profile has
  no explicit backend. An existing profile backend choice is preserved. Root
  provider configuration is not copied into the generated profile (#460).
- Failure of the optional native-wheel selector falls back to the bundled pure
  runtime. Installation health and exact wheel fingerprint checks still apply.
- Native extension libraries are signed before bundling for notarization.
- The prefill stall watchdog is configurable from both CLI and the app (#448).
- Model-store free-space checks follow configured or symlinked model locations
  (#466); this does not add a new external-folder download picker.

## Diagnostics

MTP economics now distinguish proposal cycles from copy/bonus verifier calls.
The on/off verdict uses delivered throughput against a supplied matched AR
measurement. Acceptance thresholds include the observed non-draft output and
are explicitly conditional on the measured cost and depth mix staying fixed.
No universal acceptance cutoff or automatic MTP disabling is introduced.

The harness runner records actual process exit status and treats timeouts as
failures. A completed coding task still requires a final client response and
validation of the generated artifact.
