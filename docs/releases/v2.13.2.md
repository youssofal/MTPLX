## What changed

**Faster short answers to long prompts on Inkling 2 Mini (#710).** When neither the client nor the server launch sets a draft depth, Inkling now proposes three tokens at a time. On the M5 Max, the largest gains were on 256-token answers to 4K and 16K prompts. On 1,500-token answers to 4K prompts the gains were smaller, 0.7% on Bare Speed and 4.9% on Optimized Speed. All 256 output tokens in the greedy comparison matched 2.13.1. An explicit client or launch depth still works with the normal defaults. Set `MTPLX_INKLING_DEPTH=auto` to restore per-round selection when the server uses its family launch depth and the client leaves depth unset.

**Parallel tool calls now keep their own arguments (#709).** When Inkling 2 Mini wrote each call separately in a streamed answer, MTPLX could give two calls the same index. The client received two argument objects joined together. MTPLX now gives each call its own index on both `/v1/chat/completions` and `/v1/messages`.

**Filtered sampling on Inkling 2 Mini.** When a client sets top-p or top-k, MTPLX can now choose the next token on the GPU. This works with existing Inkling 2 Mini packs. The top-p measurements in the opening table preceded the change to the default draft depth. The other top-p rates were measured on the earlier 2.13.2 candidate with the same filtered sampler. Each top-p rate in the table is the mean of two runs with the same coding prompt on an M5 Max. Each run began and ended at nominal thermal pressure. On Bare Speed, top-p 0.95 ran 13.8% below the native sampler on the 558-token prompt, 8.9% below the native sampler on the 4,142-token prompt, and 2.4% above the native sampler on the 16,430-token prompt. On Optimized Speed, top-p 0.95 ran 7.2% below the native sampler on the 558-token prompt, 9.0% below the native sampler on the 4,142-token prompt, and 7.1% above the native sampler on the 16,430-token prompt. Across 6 Inkling 2 Mini packs, 12 of 12 test requests using top-p 0.95 or top-k 40 ran every sampling round on the GPU. The earlier six-pack tests used a GPU-family simulation for older chips. In the same earlier tests, the FP16 text request ran all 128 sampling rounds on the GPU. A single round can move to the slower CPU path when the GPU cannot confirm which tokens to keep, as happened in 1 of 50 rounds in that image test.

**First-token time on Bare Speed.** Before the draft-depth change, with the 2.13.2 wheel first and last, cold prompts averaged 1.643 seconds to the first token on 2.13.1 and 1.717 seconds on 2.13.2. Both the native and greedy samplers were tested.

**Longer prompts on 24 GB Macs.** MTPLX now counts memory it can reuse before refusing a request, including memory from the image encoder. When a new request cannot fit, the server can return the error before it opens the response stream. With the simulated 24 GB limit, the fast prompt read handled 432 of 432 attention operations at 4K and 576 of 576 at 6K. On 24 to 36 GB Macs, eligible prompts now use this faster prompt read. Sampled and greedy answers can differ from 2.13.1. We tested the 24 GB limit in simulation on a 128 GB M5 Max. Testing on a physical 24 GB Mac is pending.

**Restoring a saved conversation (#710).** Repeating a request could return HTTP 500 after Inkling 2 Mini loaded a saved conversation from disk. This affected both native and greedy sampling. The 2.13.1 reproduction used a 4,167-token prompt matching the reported length. MTPLX now resumes generation at the first new token. Both greedy follow-ups completed after restoring the same saved state. The restored greedy answers matched every token in the clean answers of 128 tokens. With the reporter's server settings and a saved conversation, 2.13.1 returned HTTP 500. The corrected build generated 128 tokens at 100.6 tokens/s and matched the clean answer. On 2.13.1, the tested workaround is to restart the server with `--ssd-session-cache off`. That keeps RAM prefix reuse available for the current server session.

## Validated

The three coding clients read two local files using Inkling 2 Mini Optimized Speed. On the final wheel, 3 of three clients ran both reads from the first parallel response and answered with both file values. On 2.13.1, each first response joined the calls. Two clients recovered by retrying. The third reached the test deadline during retries.

On the build with the tool-call fix, the API replays covered repeated calls to one tool, calls to different tools and three calls in one answer.

The installed Mac app read the failing test name and both counts from an image. It gave the correct difference with top-p set to 0.95 and continued the same conversation after quitting and reopening.

## Upgrading

Choose Check for Updates in the MTPLX menu. For a command-line install, run `brew update && brew upgrade mtplx` or `pip install -U mtplx`. The tool-call fix works with your existing model pack.
